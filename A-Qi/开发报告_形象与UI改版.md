## 二、关键决策：为什么是「SVG 重绘」而不是「换成位图素材」

你给的新美术是 PNG 位图。直觉上"换成图片"最直接，但**在这个项目里会把功能弄坏**，理由如下：

1. 项目现在的形象是**程序化生成**的：`src/pet-svg.js` 用参数画出 8 表情 × 7 姿态，再由 `app.js` 按宠物状态切换 `data-expr` / `data-pose`，由 `styles.css` 用 CSS 动画驱动（呼吸 / 走路 / 睡觉 / 点头 / 升级闪光）。
2. 换成位图需要 **8 × 7 = 56 张独立透明图**（目前并没有这么多可用的单图素材，只有几张拼版设定图），而且**动画方式必须改**（CSS 对 SVG 的形变会失效），状态映射代码也要重写。
3. 那就等于**改了功能与逻辑** —— 与你「不修改项目本身的功能及逻辑」的要求冲突。

**结论**：把 `pet-svg.js` **重绘成新美术的样子**。外观全换、管线一行不动 —— 函数签名、导出常量、`data-expr`/`data-pose` 标记、UMD 双端加载全部保持，因此所有既有测试与交互零回归。

> 顺带保留了原有优点：矢量可无限缩放（任意 DPI 清晰）、体积几 KB、零外部素材依赖（符合"本地运行 / 可整体迁移"铁律）。将来若要整体换皮肤，仍只需替换这一个模块。

## 三、形象改版：逐项对照

| 项 | 旧版 | 新版 |
|---|---|---|
| 眼睛结构 | 黄绿大实心虹膜环 + 小黑瞳（看起来"眼睛是绿的"） | **白色大眼白 + 大黑瞳 + 瞳孔左上缘黄绿月牙高光 + 白点高光** |
| 身体色 | `#20202a`（带蓝味的深灰黑） | `#111214`（近纯黑，与设计板一致） |
| 头部比例 | 圆 r=42，耳窄长 | 略宽 r=47×42，耳更宽厚 |
| 内耳 | 窄条（**被后画的头部盖住，只剩细边**） | **饱满三角**（几何上移到头部轮廓之外，不再被盖） |
| 嘴 / 眉 | 深色线 —— 在纯黑脸上**等于看不见** | 改用可读色：嘴（柔和玫瑰）· 眉与闭眼弧（黄绿强调色） |
| 前爪 | 纯色椭圆（与身体糊成一片） | 同色 + 极淡"爪缝"，能分件 |
| 尾巴 | 细（13px） | 略粗（13.6px）+ 1px 极淡轮廓 |

### 3.1 一个必须说明的**有意偏离**
新版身体是近纯黑。**在深色壁纸下，纯黑阿七会"糊"进背景看不见。** 因此我给**外轮廓**加了一层 `opacity 0.16` 的极淡白色描边（浅色桌面上几乎不可见，深色桌面上能保住剪影）。

- 开关集中在 `src/pet-svg.js` 的 `RIM_OP` 常量：**改成 `'0'` 即可完全去掉**，回到"完全无描边"。
- 这是设计板里没有的处理，属于**功能取舍**，请你定：保留（推荐）还是去掉。

## 五、顺手修掉一个旧版就存在的 bug（请你留意）

**现象**：点击菜单的最后一项「🙈 隐藏阿七」**完全看不见**。

**实测数据**（在真实窗口尺寸下量出来的）：
```
菜单窗口高 344px，但内容实际高 377px → 溢出 33px
最后一项「隐藏阿七」底边在 y=377，远超卡片底边 336 → 整项被裁掉
```
**成因**：菜单窗口是 `overflow:hidden`（不可滚动），而 8 个菜单项 + 状态行的高度超过了 344px。状态文案 `🟢 工作中 02:06　+0.0 EXP` 在 176px 宽的卡片里会折成两行，进一步撑高。

**这不是本次换肤造成的** —— 我核对过：所有影响高度的属性（内边距、间距、字号、边框宽度）我都保持原值，因此**旧版同样溢出**。

**修法**（只收敛留白，不减少任何功能项）：
- 卡片内边距 `10/8 → 9/6`；经验条行外边距 `6/7 → 4/5`；状态行下外边距/内下边距 `8/8 → 5/5`
- 菜单项内边距 `7px → 4px`、项间距 `4px → 2px`
- 额外给列表加 `overflow-y:auto` 作为**保险**：万一将来状态文案更长，列表内部滚动而不是被裁掉

**修后实测**：`需要滚动 0px`、最后一项底边 `325 ≤ 卡片内底 330`、**无滚动条**。八项全部完整可见。

## 六、测试调整说明（**只有 1 条**）

`scripts/test-pet-svg.js` 原有一条断言写死了旧配色：

```js
// 旧：check('生气 = 带怒眉（颜色为瞳孔色）', ... includes(`stroke="${palette.pupil}" stroke-width="6"`))
// 新：check('生气 = 带怒眉（用强调色，纯黑身体上可见）', ... includes(`stroke="${palette.iris}" stroke-width="6"`))
```

**原因**：旧形象身体是深灰黑，怒眉用瞳孔色（`#0c0d10`）还能看见；**新形象是近纯黑**，瞳孔色画上去等于隐形。因此怒眉改用黄绿强调色。断言随之更新，并在测试文件里写明了原因。
