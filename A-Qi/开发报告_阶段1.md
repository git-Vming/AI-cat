## 三、关键技术决策

1. **数据与程序分离已落地**：数据根目录在打包后取 exe 同目录、开发期取项目根目录（`getAppRoot()`），保证 `data/`、`WorkRecords/` 不被打包进 asar，整体复制即迁移。
2. **安全桥接**：渲染层无法直接 require electron，`preload.js` 用 `contextBridge` 只暴露 `aqi.*` 受控接口，符合 Electron 安全实践。
3. **点击穿透方案**：采用"全局穿透 + 宠物本体 hover 切回"的标准桌宠做法（与参考项目 Evanfan007 一致），透明区域不挡桌面操作。
4. **占位美术**：阶段 1 用 SVG 黑猫占位，不阻塞底座开发；真实像素素材按已确认的 a 方案（MIT/CC0 开源猫）在阶段 8 落地。
5. **托盘图标零依赖生成**：`make-icon.js` 用纯 Node 内置 `zlib` + 手写 PNG 编码生成图标，避免引入 Pillow/画布库。

> **关于安装的两点补充说明（迁移相关，请 PM 知悉）：**
>
> 1. **沙箱环境的 `NODE_OPTIONS=--use-system-ca` 与 Electron 冲突**，仅在本开发沙箱出现；你本机不会有该变量，`npm start` 不受影响。
> 2. **`node_modules/` 已被 `.gitignore` 排除，不随文件夹迁移。** 这是 Electron 类项目的固有特性：`DeskPet.exe` 式的"复制即运行"依赖**打包阶段**（electron-builder，计划放阶段 9/10）。V1.0 开发期运行方式是 `npm install` → `npm start`；迁移到新电脑时，`data/ WorkRecords/ backup/` 三个数据目录整体复制即可恢复阿七的全部状态，但程序本体仍需在新机 `npm install` 一次（或等打包完成）。这不影响"数据可整体迁移"的核心原则——迁移的是**阿七本人**，不是 Electron。

## 八、阶段 1 报告勘误（阶段 2 验收后补充）

阶段 1 报告第五节提到的交互方案——"默认 `setIgnoreMouseEvents(true)`、hover 宠物本体切回可交互"——在阶段 2 验收时被证实**正是导致拖动/点击失效的根因**（整窗穿透后阿七本体收不到鼠标事件，hover 切交互根本不会触发）。该方案已在阶段 2 修正为：**窗口可交互 + CSS `pointer-events` 仅让阿七本体与卡片可点**（详见《开发报告_阶段2.md》第三节）。本段为历史记录勘误，以阶段 2 报告为准。
