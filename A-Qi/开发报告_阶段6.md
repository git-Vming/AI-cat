## 二、关键设计决策

### 2.1 三个触发条件（严格照规格 §30）

```
① 正在工作   status === 'working'（不是 working 就把档位清零）
② 不在午休   state !== 'LUNCH_BREAK'（12:00–14:00 直接跳过）
③ 提醒开启   settings.remindersEnabled !== false
```
三条同时满足才提醒。**午休期间一条都不弹。**

### 2.2 「连续工作」用什么计时

直接用 `getStatus().liveMinutes` —— 它由工时区间交集算法算出，**午休 12:00–14:00 已被自然排除**。
所以工作日里它天然等于"连续工作分钟"（上工到下工之间没有别的休息），无需另设计时器。

### 2.3 档位法：同一档位只提醒一次

`档位 = floor(工作分钟 ÷ 间隔)`；只有**档位超过已记录值**才提醒，然后把档位推进上去。

- 好处：不会每分钟重复弹窗；程序卡顿或休眠后恢复，也只补报一次，不会补一串。
- 例：第 60 分钟提醒护眼 → 第 61…119 分钟不重复 → 第 120 分钟进入护眼第 2 档并提醒。

### 2.4 提醒气泡（本次按 PM 要求重做）⭐

**PM 反馈：** 提醒原来出现在状态卡内（位置在卡片下方），希望改成**直接显示在桌面宠物阿七旁边的气泡**，并且**不自动消失，只有左键单击阿七或气泡才消失**。

**实现：做成独立无边框小窗**（而不是把桌宠主窗口扩大）。理由：

| | 方案 A：扩大主窗口 | **方案 B：独立气泡小窗（采用）** |
|---|---|---|
| 主窗口尺寸 180×200 | 要改 → 牵动拖动、点击、卡片布局（都是已验收的） | **完全不动** |
| 气泡跟随拖动 | 天然跟随 | 拖动时主进程同步移动气泡窗（一处代码） |
| 回归风险 | 高 | **低** |

**气泡规格：** 216×76 无边框透明小窗，默认贴在阿七**上方**（上方空间不够则自动放到下方），带一个朝下的尖角指向阿七；显示时同样置顶、不进任务栏。

**消失规则（严格按 PM 要求）：**
- **不会自动消失**（没有计时器、没有超时）；
- **左键单击气泡** → 消失；
- **左键单击阿七** → 消失（这一击只用来关气泡，不会顺手把状态卡也打开，避免"一击做两件事"）；
- 气泡已关闭时，点击阿七恢复原有行为（开/关状态卡）；
- 兜底：气泡上按 `Esc` 也能关。

### 2.5 「提醒不是惩罚」落到实处（规格 §31）

提醒链路**只做三件事**：写 `diag.log`、显示阿七窗口、弹出气泡。
**完全不写** `attendance.json` / `statistics.json` / `pet.json` —— 也就是**不可能**影响 EXP、等级、考勤或宠物心情（affection）。这是结构性保证，不是靠"记得别写"。

### 2.6 两个取舍（请你知道）

| 取舍 | 说明 |
|---|---|
| 档位状态**只存内存** | 程序重启后可能对**同一档位再提醒一次**（无副作用）。换取**零数据污染**——不往你的考勤/工作记录里塞提醒状态。 |
| 检查周期 **60 秒** | 提醒时间点最多**延迟 1 分钟**。低频轮询换低 CPU/内存占用（符合规格 §35 低占用要求）。 |

### 2.7 提醒频率（PM 已知悉，如需调整请说）

当前是**周期性提醒**：护眼每 60 分钟一次、久坐每 90 分钟一次。
一个 8 小时工作日约提醒：**护眼 8 次 + 久坐 5 次 = 13 次**（取消喝水后由 17 次降为 13 次）。
若你希望改成"每类每天只提醒一次"，我改一行即可。

## 七、请验收（本机）

```bash
cd D:\AI-cat\AI-cat\A-Qi

```

**A. 想快速看到气泡（不用等 60 分钟）**
1. 完全退出阿七 → 用记事本打开 `A-Qi\data\settings.json`；

7. 气泡还在时，拖动阿七 → 气泡应跟着一起移动；靠近屏幕顶部时气泡会自动翻到阿七下方。

8. 气泡存在时点阿七 → 只关气泡（不弹状态卡）；再点阿七 → 正常打开状态卡。
