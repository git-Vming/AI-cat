## 三、四个关键决策与理由

### 决策 1：形象用 **SVG 矢量自绘**，而不是位图素材

| 方案 | 问题 |
|---|---|
| 找 MIT/CC0 开源素材 | 设计板是**原创扁平黑猫**（黑身 + 大白眼 + 黄绿虹膜/内耳），网上找不到一致的；且"8 张表情不是同一只猫" |
| AI 生成位图 | 体积大（数百 KB~MB）、动作切换靠换图不连贯、透明边缘易有瑕疵、改一处要重画 |
| **SVG 自绘（采用）** | 表情/姿态**可程序化参数化**；几 KB；矢量任意 DPI 清晰；零外部依赖，符合"本地/无云/可迁移"；CPU/内存占用低（§35） |

`assets/pet/` 与程序保持分离（规格 §42）——将来要换风格，整体替换本模块即可。

### 决策 2：菜单做成**独立小窗**，而不是把主窗口撑大

设计板里的菜单是悬挂在阿七旁边的浮层。若把菜单塞进主窗口，窗口高度要从 200 涨到 ~540——**透明区域会成倍变大，明显挡住桌面操作**，直接违反规格 §35「阿七不能遮挡正常办公区域」。

独立小窗的额外好处：**主窗口 180×200 继续零改动**，已验收的拖动/点击/气泡逻辑不受影响。
菜单窗设 `focusable:false`（不抢焦点），因此点击阿七可反复开关菜单而不会引发失焦抖动。

### 决策 3：**主进程只推"语义状态"，表情/姿态映射放渲染层**

主进程负责"阿七在干什么"（工作中/提醒中/夜间睡眠/互动后…，复用阶段 7 的 `growth.computeState`），渲染层负责"长什么样"。这样：
- 数据层与表现层职责清晰，状态机逻辑仍可纯函数单测；
- 渲染层只在**状态真正变化时**才重建 SVG，不会每秒重建打断 CSS 动画。

### 决策 4：隐藏/显示动画用 **CSS 过渡**，不用窗口透明度 API

透明（`transparent:true`）窗口的 `setOpacity` 在各平台/驱动上表现不一。改为：渲染层 CSS 淡出（160ms）→ 主进程收到"已完成"后再 `hide()`。零平台风险。
