## 二、关键设计决策（这三条决定成败）

### 2.1 统计改为「全量重算」——不再增量累加 ⭐

**问题：** 阶段 2 的 `punchOut` 是「把本次工时**加到** statistics 上」。这在"只增不改"时没问题；但阶段 4 允许**修改历史记录**，增量模式会立刻出两条错：

- 把某天的 8 小时改成 4 小时 → 累加模式**减不掉**原有的 8 小时（统计偏高）；
- 重新结算同一天 → 再加一次 → **重复累加**。

**决策：** `attendance.json` 成为**唯一真相来源**，`statistics.json` 与 `pet.json` 一律由它**全量派生**：

```
attendance.json（记录）  ──recomputeAll()──▶  statistics.json（统计）
                                          └▶  pet.json（等级 / EXP）
```

- `punchOut` 也改为「写记录 → 全量重算」，与补录走同一条路径；
- 因此**修改任意历史记录都不可能让统计漂移**；
- 集成测试 22 项（阶段 2/3 的行为验证）在重构后**全部保持通过**，证明行为等价。

> ⚠️ **一处需要你知道的口径变化：** 现在 `pet.totalExp` **完全等于** `statistics.totalExp`（因为 V1.0 的 EXP 唯一来源就是工时）。阶段 7 若加入「互动/好感度」等非工时 EXP，需要为它单开字段，不能再混入 totalExp。我会在阶段 7 报告里重申。

### 2.2 补录 UI 用「普通窗口」，不用自绘面板

补录必须能输入**日期 + 上工 + 下工**，还要**关得掉**。之前自绘无边框托盘点板因改动量与可用性被你否决过，这次我不再走那条路：

- 补录窗口是一个**带系统标题栏与原生关闭按钮的普通窗口**（420×486，不可缩放）；
- 天然有「×」按钮，不存在"关不掉"的问题；
- 载体仍是同一个 `preload.js` + `contextIsolation`，安全模型不变。

**代价（如实说明）：** 它会在**任务栏**出现一个窗口项（普通窗口的正常行为）。桌宠主窗口仍不占任务栏。

### 2.3 「忘记上工」的检测规则 —— 宁可少报，不可误报

技术规格 §20 说「第二天启动时检查昨天」。我加了**两道闸**防止全新安装或休假时天天弹窗：

| 闸门 | 规则 | 为什么 |
|---|---|---|
| ① 只查昨天 | 只检查**昨天**这一天，不回溯多日 | 与规格一致；避免首次安装后被历史空白日轰炸 |
| ② 程序须已存在 | 要求 `pet.createdAt < 昨天` | 刚装上程序、昨天还没用它 → 不应指责用户"忘打卡" |
| ③ 已忽略/已有记录 | 该日 `absent`（已忽略）或有**任何**出勤记录 → 不再提示 | "忽略"必须永久生效 |

「忘记下工」则**不限日期**：只统计真实产生过的 `incomplete` 记录（这是真实用过的痕迹，不是空白）。被提醒过一次但没处理的，**下次启动会再提醒**（符合"暂不处理"语义）。

## 三、安全底线：绝不自动算超长工时

这是阶段 4 的第一红线，落地为**三层防护**：

1. **跨天拦截**：启动时 `resumeIncomplete()` 把任何"跨天仍处于 working"的记录置为 `incomplete`，且**不写入任何 totalMinutes / exp**；
2. **不进统计**：`recomputeAll` 只统计 `status === 'completed'` 的记录，`incomplete` **天然不进统计**；
3. **必须人工确认**：`incomplete` 只能通过 `repairAttendance`（用户明确给出下工时间）才能变成 `completed`。

**实测证明**（`test-repair.js`）：
```
08:00 上工 → 程序被杀 → 第二天 09:30 开机
→ 记录置 incomplete
→ 未写入任何工时/EXP
→ 统计为 0（没把第二天算进去）        ✅
→ 补录 08:00–18:00 后才得 480 分钟     ✅
```

**另一条安全约束：** 已有出勤记录（`sessions` 非空）的日期，**禁止**用"这天没上班"抹掉（返回 `has_record`）。避免误操作删掉真实数据。

## 四、数据模型变化

```jsonc
// attendance.json —— 新增 2 种取值
{
  "2026-09-28": {
    "date": "2026-09-28", "type": "workday",
    "sessions": [{ "start": "08:05", "startTs": "…", "end": "18:12", "endTs": "…", "source": "manual_repair" }],
    "totalMinutes": 487, "normalMinutes": 480, "overtimeMinutes": 7,
    "exp": 81.2, "status": "completed", "counted": true,
    "source": "manual_repair"          // ← 阶段 4 新增：normal | manual_repair
  },
  "2026-09-29": {
    "date": "2026-09-29", "type": "workday",
    "sessions": [], "status": "absent",  // ← 阶段 4 新增：这天没上班（用户已忽略）

  }

```

**校验失败原因码**：`bad_date` / `bad_start` / `bad_end` / `bad_range`（下工不晚于上工）/ `future`（不许补录未来）/ `has_record`（已有记录不可忽略）。
