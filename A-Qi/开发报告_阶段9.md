## 二、交付内容

### 2.1 设置窗口（`src/settings.html` / `settings.css` / `settings-window.js`，新增）

普通窗口（带系统标题栏，能关），6 个分区 —— 托盘「⚙ 设置」与点击阿七菜单里的「⚙ 设置」都打开它
（**替换了阶段 8 的占位提示**）。

| 分区 | 项目 |
|---|---|
| 宠物 | 名字（≤12 字，首尾空格自动裁剪） |
| 窗口 | 始终置顶开关；桌面位置显示 + 「回到屏幕中央」 |
| 健康提醒 | 开/关；护眼间隔；久坐间隔（1–600 分钟，越界自动收敛） |
| 启动 | 开机自动启动阿七 |
| 数据 | 数据目录 + 打开；概览（出勤天数/记录文件数/体积）；最近备份；**立即备份**；备份列表 + **恢复** |
| 关于 | 版本号 + 本地化声明 |

改动即保存（勾选框/输入框 change 即写盘），保存后回读归一化后的值，避免界面与文件不一致。

### 2.2 开机启动（规格 §37）

用 Electron 的 `app.setLoginItemSettings` / `getLoginItemSettings`，开发期与打包后分别登记。
设置页显示的开关状态**以系统真实登记状态为准**（用户可能在系统里手动改过）。

> ⚠️ **一处与规格不同的决定**：规格写"默认建议开启"，我实现为**默认关闭、由用户显式开启**。
> 理由：往用户系统写"开机自动启动"是敏感操作，不应替用户决定。**如果你希望默认开启，说一声我改。**

### 2.3 数据备份 / 恢复（《开发流程》阶段 9）

- **备份 = 只读复制**：把 `data/` 与 `WorkRecords/` 复制到 `backup/<YYYYMMDD-HHMMSS>/`，
  并写一份 `backup-info.json`（时间、文件数、体积）。**完全不动当前数据。**
- **恢复 = 三重保护**：
  1. 恢复前**自动**把"当前数据"再备份一次（返回 `safetyBackup` 名字，界面会告知）；
  2. 当前数据先整体 `rename` 到临时目录，备份复制回来**成功后才**删临时目录；失败则**回滚**；
  3. 界面上必须经过**内联二次确认**（说明"会覆盖当前数据、已自动另存一份"）才会执行。
- 备份名做严格校验（`^\d{8}-\d{6}(-\d+)?$`），**路径穿越等非法名一律拒绝**。

### 2.4 迁移能力（规格 §40/§41）

无代码改动即已具备（架构本来就数据与程序分离），但本阶段补上了**可机器验证的迁移测试**（见第四节）。

## 三、两个关键决策

### 决策 1：宠物名字的唯一权威 = `pet.json.name`

原先 `pet.json.name` 与 `settings.petName` 是两处存储。迁移测试当场暴露了这个隐患：
只改 `settings.petName` 会让界面显示"小黑"、而等级面板仍显示"阿七"。

现在：**`pet.json.name` 是唯一权威**，`settings.petName` 降级为镜像（由改名操作同时写入）。
`getSettingsSummary` 读的是 `pet.json.name`，两处再也不会不一致。

### 决策 2：把"隐私红线"变成**可执行的测试**，而不是一句承诺

规格 §38/§39/§28 要求"完全断网可运行""不读公司文件/微信/邮件/浏览器/键盘/屏幕""不上传"。
这些无法靠"我记得别写"保证，于是新增 `scripts/test-boundary.js`：对**全部运行时文件**做静态扫描，
出现任何网络/剪贴板/键盘/屏幕捕获/浏览器数据/邮件/微信/遥测/上传相关 API 即**测试失败**。

这样将来任何人（包括我）不小心引入一条网络调用，CI/`npm test` 会立刻拦下。

## 四、迁移测试结果（规格 §41 完整复现）

`scripts/test-migration.js` —— **26 项全过**。真实复现了规格里的流程：


| 累计工作时长 / 累计 EXP | ✅ 不变 |

| 用户手写区 | ✅ 未被程序改动 |
| 待办条目 + 勾选状态 | ✅ 不变 |
| 好感度 / 互动次数 / 已解锁道具 | ✅ 不变 |
| 设置（名字/置顶/开机启动/护眼/久坐/桌面位置） | ✅ 不变 |

另断言：数据只落在数据根目录内；`src/` 中不含任何数据文件（**程序可换、数据不能丢**，规格 §26）。
